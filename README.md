# z站书单便捷下载

在书单网页旁完成读取、选择、下载和 Excel 导出的一款 **Edge / Chrome 浏览器扩展**。

点击扩展即可打开常驻侧栏。书籍和 Excel 一起保存到以书单名称命名的文件夹，无需启动本地软件，也不用跳转到其他页面。

## 功能

| 功能 | 说明 |
| --- | --- |
| 当前页读取 | 提取书单名称、书名、作者和可用下载链接 |
| 自动完整读取 | 打开侧栏仅读取已显示内容；点击“自动读全”后按独立间隔展开，与 BOOKS 总数比对，数量一致才成功 |
| 选择与搜索 | 全选、单选，以及按书名或作者搜索 |
| 可选格式清洗 | 移除明确的系列名、宣传语、译者等附加内容，保留英文作者名；取消即可恢复原文 |
| Excel 导出 | 离线生成真正的 `.xlsx`，包含序号、书名、作者，支持冻结表头、筛选和长文本换行 |
| 按书单归档 | 选择一次父目录，自动创建或复用同名书单文件夹 |
| 按顺序启动 | 两次启动之间保留间隔，无需等前一本完成；可设置 1～10 本的同时下载上限 |
| 实时状态 | 显示每本在途书籍的进度和速度、总速度、整批进度、启动倒计时及保存/跳过数量 |
| 重复文件检查 | 同名且字节大小相同则跳过；大小不同保留两份 |

## 安装

使用支持 Side Panel API 的桌面版 Edge / Chrome。Chrome 最低版本为 116，建议使用最新版浏览器。

1. 下载此仓库源码，或下载 [Releases](https://github.com/Arthur-Miyano/z-library-booklist-downloader/releases) 中的扩展压缩包并解压。
2. 打开 `edge://extensions` 或 `chrome://extensions`，开启“开发人员模式”。
3. 点击“加载解压缩的扩展”，选择包含 `manifest.json` 的 **`browser_extension` 文件夹**。
4. 将“z站书单便捷下载”固定到浏览器工具栏。

不需要安装 Python、Node.js 或其他运行环境。Node.js 仅用于开发测试。

### 更新已有安装

等当前任务结束，关闭旧下载窗口。用新版本替换原扩展目录，然后在扩展管理页点击“重新加载”。2.x 版本点击工具栏图标直接打开侧栏；从旧版更新时浏览器可能提示确认新增的侧栏权限。

## 使用

1. 在浏览器打开书单网页并登录，点击工具栏中的扩展图标。
2. 侧栏先读取已显示书籍。需要完整书单时，设置“两批展开之间等待”（默认 3 秒，1～3600 秒，可用小数），点击“自动读全”。数量与页面标注总数一致才显示成功；遇到网页错误或限制提示停止展开。首页和搜索页不作为书单读取。
3. 勾选书籍或全选；需要时搜索、开启格式清洗。
4. 点击“选择文件夹”，选中保存书单的**父目录**。
5. 设置两次启动间隔和同时下载上限、确认下载权，点击“下载并生成书单”。首次下载按浏览器提示一次性授权 HTTPS 网站访问；之后切换镜像或文件服务器无需逐个授权，除非你撤销了权限。

全选作用于所有已加载书籍，搜索不会清除其他选择。带有“仅书目”标识的项可以导出 Excel，但没有可用下载链接。

### 保存结果

例如选择父目录 `我的书单`，当前书单名为“计算机系列丛书”：

```text
我的书单/
└── 计算机系列丛书/
    ├── 计算机系列丛书.xlsx
    ├── 编译原理 - Alfred V. Aho.pdf
    └── 现代操作系统 - Andrew S. Tanenbaum.pdf
```

书籍文件名为 `书名 - 作者.格式`，不添加 `001` 等序号。Windows 不允许的字符会被替换，完整文件名按 UTF-16 长度限制为最多 240 单元，不截断代理对，并为重名后缀预留空间。已有书籍不会自动移动。

“下载并生成书单”先保存所选书目的 Excel，再下载其中有可用链接的书籍。中途暂停或停止不会删除已保存的 Excel。

### 只导出 Excel

选择书目后点击“导出 Excel”，无需授权网站下载，也无需确认下载权。已选择父目录时直接写入书单文件夹；未选择目录时，浏览器弹出一次 Excel 保存对话框。

已有同名 Excel 不会覆盖，新的导出文件添加 `(1)`、`(2)` 等后缀。

## 下载规则

- **间隔：** 默认两次启动之间等待 60 秒，可自由设置非负秒数（支持 0 和小数），无 3600 秒上限，修改立即生效。前一本未完成也可启动下一本；请求不会同一时间成批启动。间隔不能保证避免网站限制。
- **在途上限：** 可设为 1～10 本，默认 1 本保留逐本下载习惯。设为 10 本时，按顺序启动，最多 10 本同时传输；满额时等一本结束再启动下一本。运行中调低上限不会中断已开始的任务，只暂停补入，直到在途数量低于新上限。
- **大小：** 服务器提供可靠大小时显示单本百分比；没有提供时显示已接收字节和“总大小未知”。整批进度按处理完成的书籍数量计算。
- **去重：** 在当前书单文件夹内，按文件名和字节大小检查，包含 `(1)` 等同名副本，并忽略文件名大小写。相同大小跳过，不同大小另存一份。
- **未知长度：** 先接收临时文件，再按实际字节大小比较。压缩传输的长度头不作为文件大小使用。
- **错误处理：** 请求失败、登录页、空文件、文件大小不完整或写入失败时暂停新增任务，不把错误网页保存为电子书。其他已经开始的下载可继续完成，结束后可重试失败及尚未启动的书籍。

- **响应内容校验：** PDF、EPUB、MOBI/AZW3、DjVu、FB2 检查基本格式标识；TXT 单独检查可识别的错误文本、错误 JSON、HTML 和非文本空字节。旧完成记录和同大小本地副本也会检查文件前缀，错误响应不能仅凭完成记录跳过。此检查不是完整电子书解析或内容哈希，不能保证文件可完整阅读。
- **暂停与继续：** 手动暂停会中止所有在途任务并清理未完成文件；继续时按原书单顺序重试，保留启动间隔。停止保留已完成文件，同时取消在途与后续任务。

- **重新开始与记录恢复：** 每本保存成功后，在书单文件夹写入 `.booklist-progress.json`。关闭侧栏或重新开始时，选择原父目录、读取同一书单，程序先按记录核对文件名、大小及可用的修改时间；匹配的已完成书籍直接跳过，不请求站点、不占用启动间隔。只请求失败、未完成或本地缺失/改变的文件。并行任务按逐本完成记录恢复，不会因完成顺序不同漏掉中间失败的书。
- **记录边界：** 记录只保存书籍标识（能识别时）、书名、作者、格式、文件名及本地大小/修改时间，不保存 Cookie 或下载链接。记录应与书单文件一起保留；记录损坏或读取失败时停止，提示检查该文件。旧版本已下载但没有记录的书籍，首次仍需请求以校验大小并建立记录；之后可以免请求恢复。大小/修改时间检查不是内容哈希。记录写入失败时保留已保存书籍并提示错误。

完成记录写入失败时，侧栏显示“待补写记录”。保持侧栏打开，处理目录权限或空间问题后点击“重试并继续”，只补写记录，不重新请求已保存的书籍。本次新建且未成功写入的空记录会清理，原有有效记录会保留。补写成功之前不会允许启动另一批任务。

例如上限设为 **10 本**、间隔设为 **30 秒**：第 1 本在 0 秒启动，第 2 本在 30 秒启动，第 3 本在 60 秒启动，以此类推，即使前面的书还未下载完。已有 10 本在途时，第 11 本等待空余名额和启动间隔条件都满足后才启动。

大小检查是一种重复识别规则，**不等同于内容哈希**，无法区分同名、同大小但内容不同的文件。不同书单文件夹之间不做重复检查。

下载期间保持侧栏打开。关闭侧栏、重载扩展或退出浏览器会中断任务。重新打开后选择同一父目录，可再次运行，用大小检查跳过已下载的文件。

正常失败、暂停和停止会清理本次临时文件。强制结束浏览器可能留下 `.booklist-*.part`，这些文件不会算作完成的书籍。

## 支持范围

当前解析器支持采用 **`z-bookcard`** 书籍卡片的网页，读取其 `title`、`author`、`download`、`extension` 字段。不是任意网站的通用书单解析器。

下载支持 PDF、EPUB、TXT、MOBI、AZW3、FB2、DJVU。只处理同站 HTTPS 下载入口；网站仍可能要求登录、验证或限制下载数量。

2.2 的核心逻辑和面板流程已通过自动化测试；**真实 Edge 侧栏交互及来源站下载仍需实机验收**。

## 权限与隐私

| 权限 | 用途 |
| --- | --- |
| `activeTab`、`scripting` | 用户点击扩展后读取当前网页、触发加载更多 |
| `sidePanel` | 在原网页旁显示常驻侧栏 |
| `storage` | 保存间隔设置和当前浏览器窗口的来源标签页 |
| `downloads` | 未选择目录时单独导出 Excel |
| 可选网站访问 | 下载时精确申请书单来源和实际文件服务器的访问权限 |

首次下载通过浏览器原生对话框申请 `https://*/*` 可选访问权限，覆盖所有 HTTPS 地址。已授予时不再申请；权限被撤销后，下次点击下载或继续才重新申请。镜像和文件服务器由实际下载跳转决定，不维护固定域名名单。浏览器提示的访问范围包括其他 HTTPS 网站；这项权限不增加账号下载额度，也不绕过网站登录、验证码或下载限制。

扩展只从用户选择的书籍下载入口发起请求，由浏览器跟随跳转；不自动扫描其他网站，不监听网页全部流量，也不为兼容服务器申请 HTTP 明文访问。读取已显示书目与单独导出 Excel 不申请这项权限。通用授权解决域名变化造成的权限遗漏，无法保证网站所有响应都可下载；跨域错误和文件服务器的 5xx 错误不能直接证明账号被风控。

扩展使用浏览器已有登录会话，不提取或保存 Cookie，不读取密码。目录访问由用户在浏览器原生对话框中授权。Excel 离线生成，书目不上传到外部服务，没有统计和远程脚本。失败诊断省略完整下载链接及其参数。

请只下载你有权获取的书籍。登录、验证码及网站下载额度问题应在原网页处理。

## 常见问题

**只读取了一部分书籍？**

点击“自动读全”后扩展按独立间隔逐次展开，只有读取数量与 BOOKS / 书籍标签中的总数相等才提示成功。例如 `BOOKS (127)` 必须读取到 127 本；按钮暂时不可用时会等待，触发后 15 秒没有增加书目则报告超时并保留已读内容。展开间隔与下载间隔分别设置，均不能保证避免网站限制。

若没有可识别的加载按钮、数量多于标注或未识别总数，不会误报成功。未知总数不继续自动展开。检查原网页后点击“自动读全”，或手动展开后点击“读取当前页”。导出仅包含当前已读取并勾选的书目。

**下载被暂停？**

展开“查看失败原因”。504 表示上游超时，不能据此判断账号或额度；429 表示限频，服务器返回 Retry-After 时队列在等待期内拒绝重试。401 提示登录验证，403 提示访问被拒绝。处理原网页问题后再重试。目录写入失败还应检查授权和可用空间。

**为何没有在 Edge 下载列表看到书籍？**

批量书籍通过用户授权的目录直接写入，进度在侧栏显示。只有单独导出且未选目录的 Excel 使用浏览器下载接口。

**不能选择某个文件夹？**

浏览器可能禁止访问系统目录，改选普通子目录。文件夹授权不跨侧栏关闭持久保存，下次打开需要重新选择父目录。

## 开发

原生 JavaScript、HTML、CSS，Manifest V3，无构建步骤。Excel 使用随包附带的 JSZip，运行时无需获取依赖。

```text
browser_extension/
├── manifest.json          扩展声明与权限
├── background.js          工具栏与侧栏入口
├── core.js                当前页解析、链接及文件名校验
├── clean.js               保守格式清洗
├── directory.js           文件校验、去重、错峰启动与最多10本在途
├── excel.js               离线 XLSX 生成
├── popup.html/css/js      侧栏界面
└── vendor/                JSZip 与许可证
tests/                     原生 API 模拟与断言检查
```

使用 Node.js 22 或更高版本运行：

```bash
node tests/run-tests.cjs
```

覆盖侧栏路由、权限、文件名、格式清洗、目录保存、同名大小去重、压缩与未知长度、错峰启动、10本上限、满额补位、乱序完成、动态上限、暂停重试、同名并行提交、速度采样、Excel 结构及完整面板流程。GitHub Actions 使用同一条命令。

自动化测试使用模拟的浏览器和文件系统 API，不能替代浏览器权限对话框、真实侧栏布局或网站下载链路的实机检查。

打包（PowerShell）：

```powershell
Compress-Archive -LiteralPath browser_extension -DestinationPath 浏览器下载助手.zip -Force
```

仓库不包含个人书单、下载的书籍、运行日志、缓存或旧本地程序归档。项目尚未指定开源许可证；第三方 JSZip 3.10.1 的 MIT 许可证见 [JSZip-LICENSE.md](browser_extension/vendor/JSZip-LICENSE.md)。

API 参考：[Edge 侧栏](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/sidebar) · [Chrome Side Panel](https://developer.chrome.com/docs/extensions/reference/api/sidePanel) · [文件系统访问](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。
